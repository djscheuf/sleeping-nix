# NixOS services and administration

## systemd on NixOS

NixOS uses systemd as its init system (PID 1). All system services, mounts, swap, targets, and devices are managed as systemd **units**. NixOS generates unit files from your `configuration.nix` and places them in the Nix store.

## Common systemctl commands

```bash
systemctl status <unit>            # detailed status and recent logs
systemctl start <unit>             # start a unit now
systemctl stop <unit>              # stop a unit now
systemctl restart <unit>           # restart a unit
systemctl reload <unit>            # reload configuration without restarting
systemctl enable <unit>            # start on boot (declarative config is preferred)
systemctl disable <unit>           # disable start on boot
systemctl list-units --type=service # list active services
systemctl daemon-reload            # reload unit files after manual changes (rarely needed)
```

Most NixOS services should be enabled declaratively:

```nix
{ services.openssh.enable = true; }
```

After editing, run `sudo nixos-rebuild switch` and systemd will start/stop the service as needed.

## NixOS unit paths

Units generated by NixOS live in `/nix/store` and are symlinked into the systemd system directory. You can inspect the actual unit file with:

```bash
systemctl cat <unit>
```

## User management

Create users declaratively:

```nix
{
  users.users.alice = {
    isNormalUser = true;
    home = "/home/alice";
    description = "Alice";
    extraGroups = [ "wheel" "networkmanager" ];
    openssh.authorizedKeys.keys = [ "ssh-ed25519 AAAAC3NzaC..." ];
  };

  users.groups.wheel = {};
}
```

Set a password interactively after rebuild:

```bash
sudo passwd alice
```

Or declaratively with a hashed password (use `mkpasswd` to generate):

```nix
{ users.users.alice.hashedPassword = "$y$j9T$..."; }
```

## Groups

```nix
{
  users.groups.mygroup = {
    gid = 1000;
    members = [ "alice" "bob" ];
  };
}
```

## Logging

Use `journalctl` to read systemd logs:

```bash
journalctl -u <unit>               # logs for a specific unit
journalctl -u <unit> -f            # follow logs
journalctl -b                      # logs from current boot
journalctl -xb                     # logs from current boot with explanations
journalctl --since "1 hour ago"
journalctl -p err                  # error priority and above
```

## Rescue and maintenance mode

Enter rescue mode (single-user root shell, most services stopped):

```bash
sudo systemctl rescue
```

Emergency mode (even fewer services):

```bash
sudo systemctl emergency
```

Exit by leaving the shell.

## Custom systemd services

You can define a custom service in `configuration.nix`:

```nix
{
  systemd.services.myworker = {
    description = "My background worker";
    wantedBy = [ "multi-user.target" ];
    serviceConfig = {
      ExecStart = "${pkgs.myworker}/bin/myworker";
      Restart = "always";
      User = "myworker";
    };
  };

  users.users.myworker = {
    isSystemUser = true;
    group = "myworker";
  };
  users.groups.myworker = {};
}
```

## Timers (cron replacement)

```nix
{
  systemd.services.mybackup = {
    serviceConfig.ExecStart = "${pkgs.mybackup}/bin/mybackup";
  };

  systemd.timers.mybackup = {
    wantedBy = [ "timers.target" ];
    timerConfig = {
      OnCalendar = "daily";
      Persistent = true;
    };
  };
}
```

## Necessary system state

NixOS expects these directories to persist across reboots:

- `/nix` — the Nix store and database.
- `/boot` — bootloader files (ESP, GRUB, etc.).
- `/var/lib` — service state.
- `/var/log/journal` — systemd journal.
- `/etc` — generated by activation scripts; some subdirs hold mutable state.
- `/etc/machine-id` — systemd machine ID.

## Best practices

- **Prefer declarative service configuration** over running `systemctl enable` directly.
- **Use `systemctl cat <unit>`** to inspect the generated unit file when debugging.
- **Read logs with `journalctl -u <unit>`** before asking why a service failed.
- **Define users and groups in `configuration.nix`** so they survive reinstalls.
- **Back up `/etc/nixos` or your flake repo**; that is your source of truth.
