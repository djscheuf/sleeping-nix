# Flake-based NixOS configuration

A flake-based NixOS configuration replaces the traditional channel-based `/etc/nixos/configuration.nix` setup with a `flake.nix` that pins `nixpkgs` and other inputs via `flake.lock`.

## Minimal NixOS flake

```nix
{
  description = "My NixOS configuration";

  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
  };

  outputs = { self, nixpkgs }:
    {
      nixosConfigurations.myhost = nixpkgs.lib.nixosSystem {
        system = "x86_64-linux";
        modules = [ ./configuration.nix ];
      };
    };
}
```

With this flake in `/etc/nixos/flake.nix`:

```bash
sudo nixos-rebuild switch --flake /etc/nixos#myhost
```

NixOS defaults to reading `/etc/nixos/flake.nix` if it exists, so `sudo nixos-rebuild switch` often works without `--flake`.

## Key parts

| Part | Purpose |
|------|---------|
| `nixosConfigurations.<hostname>` | Defines a NixOS system named by hostname |
| `nixpkgs.lib.nixosSystem` | Builds the full NixOS system from modules |
| `system` | Target platform (`x86_64-linux`, `aarch64-linux`, etc.) |
| `modules` | List of NixOS modules to merge |

## Passing flake inputs into configuration.nix

If you want to use other flake inputs (e.g., home-manager) inside `configuration.nix`, pass them via `specialArgs`:

```nix
{
  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
    home-manager.url = "github:nix-community/home-manager";
  };

  outputs = { self, nixpkgs, home-manager, ... }@inputs:
    {
      nixosConfigurations.myhost = nixpkgs.lib.nixosSystem {
        system = "x86_64-linux";
        specialArgs = { inherit inputs; };
        modules = [
          ./configuration.nix
          home-manager.nixosModules.default
        ];
      };
    };
}
```

Then in `configuration.nix`:

```nix
{ config, pkgs, inputs, ... }:

{
  # Use inputs.home-manager or other flakes here
  environment.systemPackages = [ inputs.home-manager.packages.x86_64-linux.home-manager ];
}
```

## Multiple hosts

```nix
{
  inputs.nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";

  outputs = { self, nixpkgs }:
    let
      mkHost = hostname: system:
        nixpkgs.lib.nixosSystem {
          inherit system;
          modules = [ ./configuration.nix ./hosts/${hostname}/hardware.nix ];
          specialArgs = { inherit hostname; };
        };
    in
    {
      nixosConfigurations = {
        desktop = mkHost "desktop" "x86_64-linux";
        laptop = mkHost "laptop" "x86_64-linux";
      };
    };
}
```

Build a specific host:

```bash
sudo nixos-rebuild switch --flake .#desktop
```

## Multi-channel / stable + unstable

You can pull in an additional Nixpkgs revision and expose it as an overlay:

```nix
{
  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-24.11";
    nixpkgs-unstable.url = "github:NixOS/nixpkgs/nixos-unstable";
  };

  outputs = { self, nixpkgs, nixpkgs-unstable }:
    {
      nixosConfigurations.myhost = nixpkgs.lib.nixosSystem {
        system = "x86_64-linux";
        modules = [
          ./configuration.nix
          ({ config, pkgs, ... }: {
            nixpkgs.overlays = [
              (final: prev: {
                unstable = import nixpkgs-unstable {
                  inherit (final) config;
                  inherit (final.stdenv.hostPlatform) system;
                };
              })
            ];
          })
        ];
      };
    };
}
```

Then use `pkgs.unstable.somePackage` in `configuration.nix`.

## Hardware configuration

After installation, `hardware-configuration.nix` is generated by `nixos-generate-config`. It contains detected filesystems, bootloader, and hardware-specific settings. Import it in your flake:

```nix
modules = [ ./configuration.nix ./hardware-configuration.nix ];
```

## Common flake commands for NixOS

| Command | Purpose |
|---------|---------|
| `sudo nixos-rebuild switch --flake .#myhost` | Apply the flake configuration |
| `sudo nixos-rebuild build --flake .#myhost` | Build without activating |
| `sudo nixos-rebuild test --flake .#myhost` | Activate but do not add boot entry |
| `sudo nixos-rebuild boot --flake .#myhost` | Build and set boot entry only |
| `sudo nixos-rebuild switch --flake .#myhost --upgrade` | Update flake inputs and apply |
| `nix flake update` | Update all inputs in `flake.lock` |
| `nix flake lock --update-input nixpkgs` | Update only `nixpkgs` |
| `nix flake check` | Evaluate flake and run checks |

## Switching from channels to flakes

1. Enable flakes in `configuration.nix`:

   ```nix
   { nix.settings.experimental-features = [ "nix-command" "flakes" ]; }
   ```

2. Run `sudo nixos-rebuild switch`.
3. Create `flake.nix` in `/etc/nixos`.
4. Run `sudo nixos-rebuild switch --flake .#<hostname>`.
5. Optionally remove channels:

   ```bash
   sudo nix-channel --remove nixos
   ```

## Best practices

- **Commit `flake.lock`**. The lock file is what makes the configuration reproducible.
- **Pin `nixpkgs` to a branch you understand** (`nixos-unstable` for latest, `nixos-24.11` for stable).
- **Use `specialArgs` sparingly**; prefer passing inputs via `imports` and module arguments where possible.
- **Keep host-specific hardware configs separate** and import them per host.
- **Run `nix flake check`** before committing to catch evaluation errors.
