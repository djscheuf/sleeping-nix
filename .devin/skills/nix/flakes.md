# Nix flakes

Flakes are a reproducible, version-pinned way to structure Nix projects. A flake explicitly declares its inputs (dependencies) and outputs (packages, shells, NixOS configurations, etc.) in a `flake.nix` file, and records exact versions in a `flake.lock`.

## When to use flakes

- You want reproducible builds with locked dependencies.
- You need to share a Nix project and have others get the same result.
- You are configuring NixOS, a development environment, or a CI pipeline.

## Basic `flake.nix` structure

```nix
{
  description = "My project";

  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
  };

  outputs = { self, nixpkgs }:
    let
      system = "x86_64-linux";
      pkgs = nixpkgs.legacyPackages.${system};
    in
    {
      packages.${system}.default = pkgs.hello;
      devShells.${system}.default = pkgs.mkShell {
        buildInputs = [ pkgs.jq pkgs.curl ];
      };
    };
}
```

## Inputs

Inputs are the dependencies of the flake. Common inputs:

| Input | Typical URL |
|-------|-------------|
| nixpkgs | `github:NixOS/nixpkgs/nixos-unstable` |
| nixpkgs stable | `github:NixOS/nixpkgs/nixos-24.11` |
| home-manager | `github:nix-community/home-manager` |
| flake-utils | `github:numtide/flake-utils` |
| local path | `path:./my-flake` |

You can reference an input in `outputs` by name. For example, with `home-manager` declared, you can use `home-manager.nixosModules.default` in a NixOS configuration.

### Input attributes

```nix
inputs = {
  nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
  nixpkgs.inputs.flake-utils.follows = "flake-utils";  # pin transitive input
};
```

## Outputs

Outputs are the artifacts the flake provides. Common output names:

| Output | Purpose |
|--------|---------|
| `packages.<system>.<name>` | Buildable packages (`nix build .#name`) |
| `devShells.<system>.<name>` | Development shells (`nix develop .#name`) |
| `apps.<system>.<name>` | Runnable apps (`nix run .#name`) |
| `overlays.default` | Nixpkgs overlay |
| `nixosConfigurations.<hostname>` | NixOS system configurations |
| `homeConfigurations.<username>` | home-manager configurations |
| `formatter.<system>` | Formatter for the project (`nix fmt`) |
| `checks.<system>.<name>` | CI checks (`nix flake check`) |

## The lock file

`flake.lock` records the exact git revisions of all inputs. It is generated by:

```bash
nix flake lock
nix flake update          # update all inputs
nix flake lock --update-input nixpkgs   # update one input
```

Commit `flake.lock` to version control to ensure reproducibility.

## Flake references

When you run `nix build nixpkgs#hello`, the part before `#` is a flake reference. Forms:

| Form | Example |
|------|---------|
| GitHub | `github:NixOS/nixpkgs/nixos-unstable` |
| GitLab | `gitlab:owner/repo/branch` |
| Path | `path:/home/alice/project` or `.` |
| URL | `https://example.com/project.tar.gz` |
| Indirect | `nixpkgs` (resolved via the flake registry) |

The part after `#` is an attribute path inside the flake outputs, e.g. `nixpkgs#hello` selects `packages.<current-system>.hello`.

## Common flake commands

| Command | Purpose |
|---------|---------|
| `nix flake init -t templates#simple` | Create a flake from a template |
| `nix flake check` | Run checks and evaluate the flake |
| `nix flake metadata .` | Show flake inputs and outputs |
| `nix flake lock` | Update or create `flake.lock` |
| `nix flake update` | Update all inputs and lock |
| `nix flake clone <ref>` | Clone a flake into a directory |
| `nix build .#default` | Build the default package |
| `nix run .#default` | Run the default app/package |
| `nix develop .#default` | Enter the default dev shell |

## Multi-system flakes

You usually want to support multiple systems. Common patterns use `nixpkgs.lib.genAttrs` or `flake-utils`:

```nix
{
  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
    flake-utils.url = "github:numtide/flake-utils";
  };

  outputs = { self, nixpkgs, flake-utils }:
    flake-utils.lib.eachDefaultSystem (system:
      let pkgs = nixpkgs.legacyPackages.${system}; in
      {
        packages.default = pkgs.hello;
        devShells.default = pkgs.mkShell {
          buildInputs = [ pkgs.jq ];
        };
      });
}
```

Without `flake-utils`, you can use `nixpkgs.lib.genAttrs`:

```nix
let
  systems = [ "x86_64-linux" "aarch64-linux" "x86_64-darwin" "aarch64-darwin" ];
  forEachSystem = f: nixpkgs.lib.genAttrs systems (system: f nixpkgs.legacyPackages.${system});
in
{
  packages = forEachSystem (pkgs: { default = pkgs.hello; });
  devShells = forEachSystem (pkgs: { default = pkgs.mkShell { buildInputs = [ pkgs.jq ]; }; });
}
```

## Flake registry

The registry maps short names to flake references. Show it with:

```bash
nix registry list
```

You can pin `nixpkgs` in the user registry:

```bash
nix registry pin nixpkgs
```

## Best practices

- **Commit `flake.lock`** in version-controlled projects.
- **Pin `nixpkgs` to a branch or tag** you intend to follow, not to a moving branch if you want stability.
- **Use `legacyPackages.<system>` for nixpkgs** because nixpkgs is not a flat flake package set.
- **Keep `outputs` lazy** — expensive computations should live inside derivations, not in flake output evaluation.
- **Use `nix flake check`** to catch evaluation errors before committing.
